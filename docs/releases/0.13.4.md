# Poly 0.13.4 — GitLab CI configuration

Status: **pending**. Version assignment is provisional.
Prerequisite: configuration generation contract established in 0.13.2;
0.13.3 precedes this in priority but is not a technical dependency.

## Purpose

Prepare reviewable CI configuration from the root-owned workspace and explicit
Poly commands, connecting local development and CI.

## Scope

- Implement a GitLab configuration driver for a bounded, supported CI profile.
- Generate a CI file or managed include with explicit command selection, runtime
  setup, reports/artifacts, and runner assumptions.
- Specify whether the profile targets a root orchestration repository or a child
  repository. Preserve independent repository ownership and existing pipelines.
- Reuse driver plan/actions, configuration ownership, facade normalization, and
  optional blueprint profiles.
- Make credentials references and environment requirements explicit without
  embedding secrets in generated configuration.
- Validate syntax and demonstrate equivalence of selected Poly operations locally
  and in the representative CI environment.

## Acceptance

Generated configuration is inspectable before application, passes the supported
GitLab configuration validation, and executes the chosen workspace scenario in
an explicitly authorized CI environment. Repeated generation and existing-file
conflicts follow the common lifecycle. Logs and reports are retrievable.
Required CI and explicit real-use acceptance are recorded.

## Exclusions

Remote project creation/settings mutation, pushing generated files, automatic
pipeline triggering, remote runners installation, and deployment authorization.
These are distinct user actions or future driver operations, not implicit effects
of configuration generation. Existing Git cloning remains in the Git driver.

## Validation marker

Planned tag: roadmap/0.13.4-gitlab-configuration.
Only tag after implementation, required CI, and explicit real-use acceptance.
