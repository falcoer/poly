# Poly 0.1–0.10 — Foundation milestones

This document preserves the detailed intent of the foundation milestones while
keeping the main roadmap concise. All milestones in this document are
**validated** and retain their immutable annotated tags.

## Shared foundation contract

The root repository owns and versions composition. Child repositories remain
independent repositories rather than submodules or tracked root content.
`poly.yaml` is the authored declaration, `poly.lock.yaml` is its reproducible
resolution, and `.poly/` contains disposable runtime state. Stable node
identities survive inspection and persistence. Every structural change is
represented by a finite plan and can be logged and reported.

## 0.1 — Canonical core and finite planning

Tag: `roadmap/0.1-core-model`.

Introduced canonical nodes, graphs, constraints, action claims, actions, and
immutable plans. Planning terminates deterministically, detects conflicts, and
does not execute work while negotiating the graph.

## 0.2 — Driver SDK and conformance testkit

Tag: `roadmap/0.2-driver-sdk`.

Defined public inspector, planner, action-handler, and capability contracts,
plus a reusable conformance suite. Drivers contribute facts and actions but do
not take ownership of global orchestration.

## 0.3 — Git reference driver

Tag: `roadmap/0.3-git-driver`.

Delivered the reference Git driver for repository inspection, materialization,
checkout, and verification. Operations are expressed as planned actions with
stable identities and deterministic diagnostics.

## 0.4 — Maven reference driver

Tag: `roadmap/0.4-maven-driver`.

Delivered the reference Maven driver and demonstrated that a technology driver
can inspect, plan, execute, and verify through the same public contracts as Git.

## 0.5 — Executor, canonical reports, and CLI

Tag: `roadmap/0.5-runtime-reporting`.

Added deterministic sequential plan execution, event collection, canonical
JSON/YAML/XML reporting, and the first coherent CLI. Reports preserve canonical
plan order independently of incidental presentation details.

## 0.6 — Constructor, persistence, and control-plane

Tag: `roadmap/0.6-constructor-control-plane`.

Added workspace construction and durable manifest, lock, plan, and run state.
The core control plane owns persistence, execution policy, failures, and
recovery rather than delegating them to drivers.

## 0.7 — External driver kit

Tag: `roadmap/0.7-external-driver-kit`.

Established the package boundary, scaffold, examples, and clean-room
conformance checks required for third-party drivers to receive the same
functional rights as built-in drivers.

## 0.8 — Root-owned workspace contract and canonical identity

Tag: `roadmap/0.8-workspace-manifest`.

Converged the early model on one root-owned workspace contract. Composition is
declared at the root, resolved into exact source identities, and hydrated into
independent child repositories without allowing filesystem accidents to change
canonical node identity.

## 0.9 — Unified jobs and verb-first CLI

Tag: `roadmap/0.9-unified-jobs-cli`.

Unified direct commands and planned work under one job vocabulary and adopted
the verb-first CLI. Command routing remains deterministic and machine-readable
output retains the same semantic model as interactive output.

## 0.10 — Root bootstrap and recursive Git hydration

Tag: `roadmap/0.10-git-materialization`.

Completed root workspace bootstrap and recursive hydration of Git-backed nodes
at locked commits. Hydration is repeatable, refuses unsafe movement of adopted
dirty repositories, and keeps root and child repository ownership separate.

## Historical acceptance rule

Each milestone above was accepted only after its implementation and tests were
green and its annotated tag was created. Exact historical criteria remain
available in Git history at the corresponding tag; this document records the
durable product contract rather than reproducing obsolete implementation plans.
