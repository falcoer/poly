# Poly 0.10.2 — Runtime output corrections

Status: **validated**. The authoritative acceptance criteria and validation state
are maintained in
[the roadmap](../../ROADMAP.md#0102--runtime-output-and-release-identity-corrections).

## Purpose

Several runtime and CI corrections landed after the validated 0.10.1 tag. The
package still identified itself as `0.1.0.dev0`, so an installation did not
reveal which functional milestone it contained. Version 0.10.2 packages those
corrections without claiming the later 0.11 driver-runtime scope.

## Delivered

- direct CLI verbs stream their execution progress before the completion block;
- successful empty runs display a neutral `NONE` state;
- CI verifies that an existing milestone tag targets an ancestor of the commit
  being validated;
- the package metadata, public Python API, and `poly --version` share the same
  `0.10.2` version source.

## Installation identity

After installation, the exact functional baseline is visible directly:

```shell
poly --version
# poly 0.10.2
```

Python consumers can read the same value from `poly.__version__`, while wheel
and source-distribution filenames and metadata use `0.10.2` as well.

## Validation evidence

The later 0.11 CI was not treated as sufficient evidence for 0.10.2 because it
built and identified version 0.11.0 rather than the exact 0.10.2 distribution.
A dedicated remote validation therefore checked out commit
`1c1346cb032b3429095091f173e5c6a5b766383c` and executed the complete Linux and
Windows gates, formatting, lint, strict typing, tests with the coverage gate,
clean-room external-driver validation, wheel/sdist build, and explicit 0.10.2
package/CLI metadata checks.

GitHub Actions run `33598204087` completed successfully and created the immutable
annotated tag `roadmap/0.10.2-runtime-corrections`. The tag object targets exactly
`1c1346cb032b3429095091f173e5c6a5b766383c`; it is not inferred from the later
0.11 tag and must never be moved.
