# Poly 0.13.3 — VS Code and OpenCode preparation

Status: **pending**. Version assignment is provisional.
Prerequisite: 0.13.2 configuration lifecycle validated.

## Purpose

Prove reuse across two additional tool formats without adding technology-specific
branches to the engine. Deliver and review each driver incrementally.

## Scope

- VS Code driver: multi-root workspace generation and a bounded profile of
  settings, extension recommendations, tasks, and debugging configuration.
- OpenCode driver: a bounded profile of workspace context, instructions, commands,
  and integration configuration. Verify the supported tool version and actual
  schema during implementation; these categories are not assumed API field names.
- Reuse public facade/blueprint contracts where useful; all effects use planned
  driver actions. Drivers own their respective configuration formats.
- Preserve user configuration and references to credentials. Use explicit policy
  for workspace-shared versus local settings, including per-tool precedence.
- Declare managed paths/resources to detect collisions between generators.
- Maintain separate supported-version documentation and cookbook journeys.

## Acceptance

Each driver prepares a representative workspace usable in its target tool.
Repeated generation is stable, unrelated customization survives, generated
configuration validates against the supported target version, and conflicts are
reported. External plugin conformance and required Windows/Linux CI remain green.
Record explicit real-use acceptance for both tools before closing the milestone.

## Exclusions

Automatic installation of tools/extensions, launching an AI session, autonomous
agent execution, tool permission changes, and a universal editor configuration
language. A plugin package need not match a single contribution type.

Planned tag: roadmap/0.13.3-editor-configuration.
Only tag after implementation, required CI, and explicit real-use acceptance.
