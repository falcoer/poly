# Poly 0.10.1 — Daily workflow correction

Status: **implemented, awaiting complete CI**. The authoritative acceptance criteria and validation
state are maintained in [the roadmap](../../ROADMAP.md#0101--daily-workspace-authoring-and-cli-clarity).

## Purpose

Version 0.10 restored root bootstrap and recursive Git hydration. Real-world
authoring with a large workspace exposed two corrections required before 0.11:

1. declaring a repository must remain a lightweight composition change;
2. interactive output must make each command and its result immediately clear.

The release also completes the previously specified contextual nature workflow
and guarantees that built-in drivers remain visible from an empty workspace.

## Delivered

The interactive text renderer now produces one visual block per command:

- an action-oriented heading such as `ADDING`, `HYDRATING`, or `VERIFYING`;
- an indented plan and one status line per action;
- distinct success, failure, warning, and blocked markers with terminal colors;
- a separately framed final success or failure result;
- `-q`, default, `-v`, and `-vv` detail levels;
- `--color auto|always|never` and standard `NO_COLOR` support.

Machine-readable JSON, YAML, and XML reports remain unchanged.

Source-backed `poly add` now resolves the requested selector and atomically
updates `poly.yaml`, `poly.lock.yaml`, the managed `.gitignore` block, and
compiled state without clone, fetch, adoption, checkout, or child-path creation.
The selector remains authored intent and the lock retains the exact advertised
commit. `poly hydrate` is the explicit idempotent materialization command.

`poly nature list` reports driver-contributed natures alphabetically. Contextual
`nature add` and `nature remove` find the nearest workspace and current declared
node, accept `.`, and handle multiple natures. `poly drivers` is regression-tested
from an empty directory.

## Implemented behavior

### Lightweight add

A source-backed declaration follows this contract:

```text
poly add
  ├─ update poly.yaml
  ├─ resolve the requested Git selector
  ├─ update poly.lock.yaml with the exact commit
  ├─ reconcile the managed .gitignore block
  └─ do not clone, fetch, adopt, checkout, or hydrate
```

A successful `add` is therefore immediately committable and ready for a later,
explicit `poly hydrate`. Manifest, lock, generated state, and ignore changes
must remain atomic when resolution fails.

### Intent and lock

`poly.yaml` records what should be followed, such as a branch, exact tag, or
commit. `poly.lock.yaml` records the immutable commit selected at resolution
time. Hydration consumes the lock and does not reinterpret moving references.

Advanced policies such as tag patterns and SemVer constraints are intentionally
deferred beyond 0.10.1.

### Contextual natures

The release must provide:

```shell
poly nature list
poly nature add . maven/reactor
poly nature add . nature/one nature/two
poly nature remove . maven/reactor
```

The current directory resolves through the nearest Poly workspace, and
`nature list` is assembled from loaded drivers in alphabetical order.

### Driver visibility

`poly drivers` must list built-in and system drivers even when the current
workspace contains no nodes. This behavior requires an explicit regression test.

## Validation gate pending

0.10.1 becomes `validated` only when:

- source-backed `add` has no child-worktree side effect;
- explicit hydration restores every locked source and remains idempotent;
- contextual and multiple-nature commands pass on Windows and Linux;
- empty-workspace driver enumeration passes;
- interactive and structured renderers pass their parity and snapshot tests;
- formatting, lint, strict typing, unit tests, the 90% coverage threshold, and
  package builds all succeed;
- CI creates the annotated tag `roadmap/0.10.1-daily-workflow`.
