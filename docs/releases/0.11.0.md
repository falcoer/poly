# Poly 0.11.0 — Runtime driver lifecycle and inventory

Status: **implemented, awaiting CI validation**. The authoritative acceptance
state is maintained in
[the roadmap](../../ROADMAP.md#011--runtime-driver-lifecycle-and-inventory).

## Delivered

- the production registry loads installed `poly.drivers` entry points beside
  system and built-in drivers;
- installed inspectors enrich existing canonical nodes, planners contribute
  actions and direct CLI verbs, and handlers execute through the public SDK;
- `poly drivers` exposes name, version, origin, API protocol, capabilities,
  verbs, load status, entry-point identity, and rejection diagnostics;
- duplicate identities, incompatible protocols, import failures, and installed
  verb collisions are isolated deterministically;
- driver discovery and load state are embedded in canonical inspection, action,
  plan, and run reports with text, JSON, YAML, and XML parity;
- a generated sample-driver wheel is installed with the Poly wheel in a clean
  environment and exercised through inventory, direct execution, and persisted
  report retrieval.

## Installation identity

The Python public version, CLI output, wheel metadata, source-distribution
metadata, and artifact filenames all use the single `0.11.0` version source:

```shell
uv tool install ./dist/poly-0.11.0-py3-none-any.whl
poly --version
# poly 0.11.0
```

## Compatibility and security

Drivers must target protocol `1.0` and depend only on the public `poly.driver`,
`poly.driver.testkit`, and `poly.model` interfaces. Workspace files remain
compatible with the 0.10.2 baseline.

This release does not sandbox hostile drivers. A trusted installed driver's
module and factory run inside the Poly process with the invoking user's
permissions. Review driver distributions before installation.

## Validation gate

The milestone remains `implemented-awaiting-ci` until the full Linux and Windows
matrix, strict formatting/lint/typing, at least 90% coverage, wheel and sdist
builds, clean-room installed-driver journey, and artifact metadata checks pass
remotely. Only then may the annotated tag
`roadmap/0.11-driver-runtime` identify the validated commit.
