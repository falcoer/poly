# Poly 0.12.0 — Clean-workstation functional acceptance

Status: **implemented, awaiting CI validation**. The authoritative state is maintained in [the roadmap](../../ROADMAP.md#012--clean-workstation-functional-acceptance). The release must not be marked `validated` until the implementation is merged, the complete `main` CI is green, and the immutable annotated tag `roadmap/0.12-functional-baseline` is verified on the exact accepted commit.

## Purpose

0.12.0 is the first release gate that proves the complete minimum Poly journey on clean Windows and Linux hosts from retained package artifacts rather than from a source checkout.

A reviewer receives a wheel, source distribution, SHA-256 manifest, a deterministic acceptance fixture, an installed external-driver wheel, and machine-readable evidence. The clean-room jobs intentionally do not use `actions/checkout`.

## Acceptance fixture

The fixture is generated deterministically by `tools/acceptance/build_fixture.py` with fixed Git author and committer dates. It contains:

- one root control repository whose committed content includes `poly.yaml`, `poly.lock.yaml`, the Poly-managed `.gitignore` block, and an external-driver marker file;
- two independent Git child repositories, `alpha` and `beta`, locked to exact commits;
- an `alpha` Maven reactor with two declared modules;
- portable local bare remotes used only by the acceptance journey;
- `fixture-commits.json`, which records the exact root and child commits and the expected canonical node identifiers;
- a generated `poly-driver-sample-tech` wheel installed beside the retained Poly wheel;
- equivalent POSIX and PowerShell entry scripts.

The fixture is test input. It is not generated Poly state and it is not user workspace persistence.

## Generated artifacts and persistent data

Three categories are deliberately distinct:

1. **Acceptance fixture** — deterministic test input distributed as a CI artifact.
2. **Generated validation artifacts** — wheel, sdist, checksums, build metadata, reports, action logs, inventories, Git snapshots, environment metadata and readable summaries retained by GitHub Actions.
3. **Persistent workspace data** — committed `poly.yaml`, `poly.lock.yaml` and the root `.gitignore` composition contract. `.poly/` remains disposable generated state and is explicitly deleted and reconstructed during acceptance.

## Demonstrated journey

From an empty target and only the root repository URL, one `poly init` must:

- clone the root control repository;
- validate its committed manifest and lock;
- restore both independent child repositories at their locked commits;
- inspect the multi-module Maven reactor;
- load the installed external driver;
- persist a normal report containing the bootstrap and recursive-hydration phases.

The same clean-room run then proves that:

- `poly drivers`, `poly inspect`, `poly status` and `poly verify` preserve the manifest's canonical identifiers;
- Maven `verify` really executes on the retained fixture;
- the external driver's `sample-status` verb really executes through the production registry;
- `poly report <run-id>` recovers the bootstrap run in text, JSON, YAML and XML;
- JSON, YAML and XML decode to the same canonical `poly.report/v1` meaning and the text view contains the same plan actions and final state;
- deleting `.poly/` and inspecting again reconstructs an equivalent canonical inventory;
- a second hydration changes no authored file hash, non-generated worktree content, root Git index tree, child HEAD or Git status;
- modifying a child worktree leaves the root repository clean;
- modifying `poly.yaml` makes the root repository dirty.

## Retained CI evidence

For each accepted commit, CI retains:

- `poly-0.12.0-py3-none-any.whl`;
- `poly-0.12.0.tar.gz`;
- `SHA256SUMS`;
- `build-metadata.json` with commit, version, artifact names, sizes and SHA-256 values;
- the deterministic acceptance fixture and external-driver wheel;
- POSIX and Windows acceptance evidence, including `report.txt`, `report.json`, `report.yaml`, `report.xml`, `report-parity.json`, `action-logs.json`, canonical inventories before and after reconstruction, `idempotence.json`, `git-states.json`, `fixture-commits.json`, `environment.json`, command stdout/stderr files and `SUMMARY.md`;
- quality evidence including coverage and JUnit output.

## Installing the retained wheel without a Poly checkout

Use the CI run and commit shown by the accepted release evidence. The artifact names include the exact commit SHA.

### POSIX

```bash
run_id="<accepted-run-id>"
commit="<accepted-commit>"

gh run download "$run_id" -R falcoer/poly \
  -n "poly-0.12.0-distributions-$commit" -D poly-dist
gh run download "$run_id" -R falcoer/poly \
  -n "poly-0.12.0-acceptance-fixture-$commit" -D poly-fixture

(cd poly-dist && sha256sum -c SHA256SUMS)
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install ./poly-dist/poly-0.12.0-py3-none-any.whl \
  ./poly-fixture/poly_driver_sample_tech-0.1.0-py3-none-any.whl

./poly-fixture/scripts/run-posix.sh \
  "$PWD/.venv/bin/python" \
  "$PWD/.venv/bin/poly" \
  "$PWD/poly-fixture" \
  "$PWD/poly-evidence"
```

### PowerShell

```powershell
$runId = "<accepted-run-id>"
$commit = "<accepted-commit>"

gh run download $runId -R falcoer/poly `
  -n "poly-0.12.0-distributions-$commit" -D poly-dist
gh run download $runId -R falcoer/poly `
  -n "poly-0.12.0-acceptance-fixture-$commit" -D poly-fixture

$sumLine = Get-Content .\poly-dist\SHA256SUMS |
  Where-Object { $_ -match "poly-0.12.0-py3-none-any.whl$" }
$expected = ($sumLine -split "\s+")[0].ToLowerInvariant()
$actual = (Get-FileHash .\poly-dist\poly-0.12.0-py3-none-any.whl -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw "Poly wheel SHA-256 mismatch" }

py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install `
  .\poly-dist\poly-0.12.0-py3-none-any.whl `
  .\poly-fixture\poly_driver_sample_tech-0.1.0-py3-none-any.whl

& .\poly-fixture\scripts\run-powershell.ps1 `
  -PythonExe .\.venv\Scripts\python.exe `
  -PolyExe .\.venv\Scripts\poly.exe `
  -FixtureDir .\poly-fixture `
  -OutputDir .\poly-evidence
```

Both routes install and execute retained wheels. Neither requires a clone or checkout of Poly source code.

## Exclusions

0.12.0 does not add a Web UI, parallel execution, child repository commit/push/merge workflows, publication to a public package index, or hostile-driver sandboxing. External drivers remain trusted in-process code.
