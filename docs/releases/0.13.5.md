# Poly 0.13.5 — Angular creation through contributions

Status: **pending**. Version assignment is provisional.
Prerequisites: 0.13.1 contribution contracts and 0.13.2 generation lifecycle.
This follows the configuration drivers in product priority.

## Purpose

Deliver the user's 2026-09-02 scenario: add an existing empty GitLab repository,
then create an Angular application/UI inside it.

## Scope

- Reuse Git add/hydrate for repository declaration and materialization.
- Provide Node technology inspection, nature attribution, and bounded package
  manager/build/test operations. Choose and document one supported package
  manager/version policy first.
- Provide Angular-specific generation knowledge and a versioned application
  blueprint with validated parameters and resources.
- Provide a creation facade yielding canonical intent compatible with preparation.
  Decide exact CLI syntax during design; examples from prior discussion are not
  existing commands.
- Return finite generation actions with explicit facts/resources/outputs. Keep
  Angular and package-manager logic outside the core.
- Handle empty-target requirements, generated-file ownership, repeat application,
  partial failure, and absent tools explicitly. No silent overwrites or installs.
- Inspect the newly created project before a subsequent build/test command.
  Do not discover new actions during the frozen creation run.
- Offer the already delivered tool-configuration profiles where applicable through
  explicit subsequent preparation commands.

## Acceptance

From an existing empty remote repository, the documented Poly journey declares
and materializes it, generates the application, inspects its natures, and builds
and tests it using explicit commands. Preparation performs no generation.
Unsupported input and collisions are diagnosed; results expose artifacts/logs.
Blueprint/plugin/tool versions needed to reproduce creation are recorded.
The plugin passes public SDK conformance and required Windows/Linux checks;
explicit real-use acceptance is recorded.

## Exclusions

Creating the remote GitLab project, arbitrary Angular schematic coverage,
automatic installation of Node, multi-language plugin transport, Docker/SonarQube
enrichment, and general nested blueprint orchestration. A second blueprint or
enrichment is backlog work driven by a concrete need.
