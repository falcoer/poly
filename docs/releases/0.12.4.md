# Poly 0.12.4 — Interactive rendering corrections

Status: **in-progress**. This corrective release intentionally remains open because one additional correction is still being prepared before the scope is frozen.

## Purpose

0.12.4 is a presentation-only corrective release on top of 0.12.3. It does not change prepared-command semantics, plan resolution, execution ordering, or persisted report meaning.

## Current corrections

### Planned-command block

Prepared commands must render with the user-authored command heading in the terminal's default foreground color, without a horizontal rule above it. The planned status is shown as a three-line magenta body with a white vertical gutter, followed by one white horizontal separator below the block.

```text
ADDING 361-admin-check-src from https://example.invalid/361-admin-check-src.git (ref: P17) ...
│  ○ PLANNED  poly add
│    75 commands in current plan
│    Run `poly exec` when the plan is ready.
────────────────────────────────────────────────────────────
```

This rule applies generally to interactive command announcements: no horizontal separator is emitted before the command heading; separators belong below the announced command block.

### Execution progress label

The transient global progress row uses `IN PROGRESS` instead of `PLAN` so that it describes execution state rather than the frozen plan object. Warning and failure variants retain the same wording prefix (`IN PROGRESS WARN`, `IN PROGRESS KO`).

## Acceptance

- command headings use the terminal default foreground color and are never preceded by a horizontal separator;
- prepared-command bodies retain magenta status text while their vertical gutter and final separator are white;
- the planned block contains exactly one final horizontal separator;
- the progress row no longer uses `PLAN` as its execution-state label;
- redirected/plain text output preserves the same structure without ANSI control sequences;
- JSON, YAML, and XML canonical report semantics remain unchanged;
- the complete quality, Windows/Linux, fixture, clean-room, and acceptance CI remains green.

## Scope status

The release scope is not final yet. One additional correction is expected to be added before 0.12.4 is marked implemented or proposed for merge.
