# Poly 0.12.4 — Interactive rendering and Git hydration corrections

Status: **validated**. This document is the authoritative detailed scope; the
[roadmap](../../ROADMAP.md#0124--interactive-rendering-and-git-hydration-corrections)
is its compact index.

Validation was explicitly supplied after the hydration corrections and final
terminal refinements were accepted in real use. The final integrated state
passed 235 tests with 90.25% coverage and GitHub Actions run `34137233314` on
commit `0b37958f04fa5c0ac69e4cd088321512ed263d01`. The annotated milestone tag is
created on the documentation commit that records this explicit validation.

## Purpose

0.12.4 is a corrective release on top of 0.12.3. It includes interactive rendering corrections plus a Git hydration fix for fresh `--no-checkout` clones whose locked commit differs from the remote repository HEAD.

## Current corrections

### Planned-command block

Prepared commands render with the user-authored command heading in the
terminal's default foreground color and a compact magenta planned result. The
early framed proposal was superseded by the smaller 0.12.5 presentation during
real-use validation.

```text
ADDING 361-admin-check-src from https://example.invalid/361-admin-check-src.git (ref: P17)
 ○ Planned (75 commands prepared in current plan)
```

No decorative frame or separator is emitted for this two-line announcement.

### Execution progress label

The transient global progress row uses `IN PROGRESS` instead of `PLAN` so that it describes execution state rather than the frozen plan object. Warning and failure variants retain the same wording prefix (`IN PROGRESS WARN`, `IN PROGRESS KO`).

### Fresh Git hydration at the locked commit

`poly hydrate` materializes missing repositories with `git clone --no-checkout`. A fresh no-checkout clone can legitimately appear dirty because its index references tracked files while the worktree has not been populated yet. Previously, when the clone's initial HEAD differed from the commit recorded in `poly.lock.yaml`, the checkout phase interpreted that synthetic deletion set as user changes and failed with `refusing to move dirty worktree`.

0.12.4 distinguishes a clone created by the current materialization from an adopted checkout. A fresh clone bypasses the user-worktree dirty guard, is force-populated at the exact locked commit, and is then returned clean. Existing/adopted repositories retain the strict dirty-worktree protection.

A persistent marker under `.git` also records an incomplete fresh materialization until checkout succeeds, so an interrupted 0.12.4 hydration can be retried safely without losing the distinction between a fresh Poly clone and an adopted user worktree.

### Repository clone depth

Git-backed repository nodes are cloned with the complete history by default. A
shallow clone can be requested when declaring the repository:

```text
poly add repository service --path service \
  --repo https://git.example/service.git --ref main --depth 1
```

The value is persisted as `source.depth` in `poly.yaml` and `poly.lock.yaml`.
It must be a positive integer. Omitting it keeps the complete-clone behavior.

Hydration can override the persisted depth for one execution without changing
the manifest or lock:

```text
poly hydrate --depth 1
```

An existing shallow checkout can be expanded to complete history with:

```text
poly hydrate --unshallow
```

The text completion line also reports the total execution time and the longest
timed action. Structured run reports expose the same information through
`run.duration_ms` and `run.slowest_action`.

## Acceptance

- command headings use the terminal default foreground color and are never preceded by a horizontal separator;
- prepared-command results retain magenta status text without a frame or separator;
- the progress row no longer uses `PLAN` as its execution-state label;
- redirected/plain text output preserves the same structure without ANSI control sequences;
- JSON, YAML, and XML canonical report semantics remain unchanged;
- a missing repository can be hydrated when the locked commit predates the current remote branch HEAD;
- a fresh no-checkout clone is populated exactly at the locked commit and ends with a clean worktree;
- an adopted dirty checkout is still refused before moving HEAD;
- an interrupted 0.12.4 fresh hydration remains distinguishable from an adopted checkout until population succeeds;
- the complete quality, Windows/Linux, fixture, clean-room, and acceptance CI remains green.
- `poly hydrate --depth N` overrides clone depth only for the current run;
- `poly hydrate --unshallow` expands shallow repositories safely;
- the final text line reports total duration and the slowest action compactly.

## Scope status

The interactive rendering, fresh Git hydration, clone-depth, and timing
corrections are implemented and validated. Later terminal-layout refinements in
0.12.5 supersede the early presentation sketch, not the 0.12.4 runtime contract.
