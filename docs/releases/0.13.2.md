# Poly 0.13.2 — Configuration generation and Eclipse preparation

Status: **pending**. Version assignment is provisional.
Prerequisite: accepted 0.13.1 contracts.

## Purpose

Prepare an existing workspace for Eclipse, continuing the Oomph-replacement
objective and proving generation as an ordinary driver operation.

## Scope

- Implement an Eclipse technology driver through the public plugin SDK.
- Select a useful bounded preparation profile from the actual workspace:
  project selection/import preparation, preferences, and launch configurations
  are candidates; record the exact supported subset before implementation.
- Use a facade for normalized preparation intent and the minimal blueprint only
  where a reusable profile adds value. Do not require a blueprint for every file.
- Define ownership of generated files, user files, and managed sections; declare
  outputs, affected paths, preconditions, conflicts, and execution resources.
- Provide reviewable planned changes, deterministic content, no-op regeneration,
  and a diagnostic for incompatible/manual modifications. Tool-specific merging
  stays in the driver. A stale plan must not silently overwrite intervening edits.
- Define provenance and any safe removal policy without relying on .poly as the
  sole durable record of user intent. Keep shared and machine-local settings distinct.
- Expose generation failures and delivered files through normal action results.
- Document preparation and use in the cookbook.

## Acceptance

A representative existing workspace can be prepared and opened in Eclipse using
the documented supported profile. Repeating generation leaves unchanged files
unchanged; customization outside the managed scope survives. Collisions and stale
inputs fail with actionable evidence. Windows paths and supported POSIX behavior
are verified, required CI is green, and real-use acceptance is recorded.

## Exclusions

Installing Eclipse/JDKs, full Oomph feature parity, global preference replacement,
unbounded configuration merges, runtime plan expansion, and a separate projection
registry or generate protocol. Automated launch is not implied.
